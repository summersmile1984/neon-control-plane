## M2 主机名与 TLS

- [x] **T-201 pg_sni_router 接入**：**放弃，2026-09-07，理由是实测**。跑起来了，然后测出两条硬事实：
  1. 它把 SNI 第一个标签按 `--` 切成三段并直接索引第 3 段，所以 Neon 连接串的单标签主机 `ep-xxx.db.siteops.localhost` 会让会话线程 panic：`index out of bounds: the len is 1 but the index is 2`（`pg_sni_router.rs:326`，build 8464）。
  2. 换成它认的 `<svc>--<ns>--<port>` 形状后，它把目标拼成 `<svc>.<ns>.<destination>:<port>`，这是 Kubernetes 的 Service DNS 名，compose 网络里对不上；而且它**不做鉴权、也不能唤醒挂起的 compute**。
  
  T-302 的 proxy 覆盖它的全部用途且多做鉴权与唤醒，因此 compose 里删掉该服务。`sni-router` 路由档保留在 `src/domain/connection-uri.ts`（k8s 部署下那个三段标签是对的），但本地栈不提供对应的路由器，本地开发一律用 `proxy`。自签通配证书 `infra/compose/certs/wildcard.{crt,key}` 保留给 proxy 用（**subject 只能有 CN**，带 `O=` 会让 proxy 报 `Failed to parse common name from certificate`）。
- [x] **T-202 Caddy 与 SiteOps 接线**：**已完成 2026-09-07**。SiteOps `infra/local/Caddyfile` 增 `neon-api.siteops.localhost:8443 → http://127.0.0.1:8080`，hosts 清单同步。  
  验收：`curl https://neon-api.siteops.localhost:8443/healthz` 200（已跑）；T-110 的整条链路都走它。
- [x] **T-203 Directus 走控制面连接串**：**已完成 2026-09-07**。Directus 用本控制面发的 URI 启动并跑完全部引导迁移：**33 张 `directus_*` 表、107 条迁移、1 个 admin 用户**，全部落在控制面起的 compute（`inet_server_port()=55433`，PostgreSQL 17.5）。  
  连接串形状：`postgresql://<role>:<pw>@host.docker.internal:5434/<db>?sslmode=no-verify&options=endpoint%3D<ep>`。容器看到的 proxy 是 `host.docker.internal`，端点 id 塞不进这个主机名，所以走 Neon 的启动包回退参数 `options=endpoint=`（已实测 proxy 支持，且这条路径完全不依赖 DNS）。  
  验收：`tests/e2e/directus-on-control-plane.test.ts` 3 用例通过（已跑）。用例自带跳过条件：本地没有 `siteops-directus-container` 镜像时报跳过而不是失败。  
  **顺带测出的行为**：compute 真的挂起后，Directus 的第一个请求会**立刻 503**（3 ms，不是超时），proxy 在后台完成唤醒，下一个请求 200。这与 Neon 云端 scale-to-zero 的行为一致，长驻服务需要的是重试而不是更长的超时。

## M3 proxy 与挂起唤醒

- [x] **T-301 cplane 内部 API**：**已完成 2026-09-07**。`src/http/routes/cplane.ts` 实现 `get_endpoint_access_control` 与 `wake_compute`（含按需唤醒 idle compute、`cold_start_info`、`CP_PROXY_TOKEN` 鉴权）。

- [x] **T-302 proxy 接入**：**已完成 2026-09-07**。compose 的 `proxy` profile 起官方 proxy，`--auth-backend=control-plane`，token 走 `NEON_PROXY_TO_CONTROLPLANE_TOKEN`。psql 经 TLS + SNI 连上真 compute（PostgreSQL 17.5），挂起后**冷启动 1.2 秒**唤醒并读到挂起前写入的数据。  
  验收：`tests/e2e/proxy-connect.test.ts` 5 用例通过（已跑）。  
  接通过程测出四条事实，每条都对应一个"错了就只报模糊错误"的坑：
  1. **`--auth-endpoint` 结尾不能带斜杠**。proxy 自己用斜杠拼方法名，带了就变成 `/cplane//get_endpoint_access_control`，控制面 404。路由侧也顺手接受了双斜杠形式作为兜底。
  2. **错误体必须是 `ControlPlaneErrorMessage { error, http_status_code, status }`**，不是 v2 的 `GeneralError { code, message }`。给错形状时 proxy 记 ``failed to parse error body: missing field `error` ``，然后对客户端报 `reason unclear (malformed error message)`——真实原因被完全吞掉。现在 `/cplane` 前缀下的 `onError`、`notFound` 和处理器异常统一用这个信封。
  3. **`cold_start_info` 没有 `cold` 这个值**。合法枚举是 `unknown / warm / pool_hit / pool_miss / http_pool_hit / warm_cached`；发 `cold` 会让整个 wake_compute 响应反序列化失败（`unknown variant \`cold\``），客户端只看到 `Control plane request failed`。从零起 compute 对应 `pool_miss`。
  4. **不要开 `--is-private-access-proxy=true`**。该模式要求每个会话带 VPC endpoint id，本地客户端都不带，直接被拒。
  
  另外：`wake_compute` 现在在请求线程里主动 `reconciler.drain()`，而不是等后台 tick——proxy 在这个 HTTP 调用上阻塞着客户端。`claimNext` 是 CAS，和后台循环并发安全。宿主机 5432 被本机 PostgreSQL 占用，所以 `PROXY_PORT` 可配，实测用 5434。

- [x] **T-501 本地运维 console**：**已完成 2026-09-07**。`/` 与 `/console` 出页面，`/console/state` 出一次性聚合快照（与 `/api/v2` 同一把 API key）。

  **只读**：页面上每个动作都打真正的 `/api/v2` 路由，所以 console 走的合同和 `provider-neon`、`neonctl` 完全一致，不存在会漂移的私有后门。它挂在 `/api/v2` 之外，不过 OpenAPI 校验，也不允许任何客户端依赖。与 SiteOps Console 无关：那是租户面产品，这个只管本机 Neon 栈。

  **唯一新增的能力是 v2 给不出来的那件事：漂移检测**（`container_missing` / `container_stopped` / `still_running`）。已实机验证：起一个 endpoint，背着控制面 `docker rm -f` 掉它的容器，console 立刻标红"状态是 active，但容器已经不在了"，点"启动"后漂移归零。docker 不可达时容器状态是 `unknown` 且**不报漂移**——连不上 docker 不构成"有问题"的证据。

  验收：`tests/contract/console-state.test.ts` 8 用例通过（已跑）。其中两条是硬约束：**快照里不能出现任何口令或 SCRAM verifier**（它要遍历全栈的 role，一个粗心字段就等于把整机口令发给任何能打开页面的人；只回 `has_stored_password` 布尔值，口令仍然只能经 v2 的 `reveal_password` 对单个 role 显式索取）；**页面不能引用 CDN**（本地工具必须断网可用，单文件、无构建）。

  两个实现决定是被真实故障逼出来的：容器状态**不缓存**（原先 2 秒缓存会让快照在每次 start/suspend 之后说 2 秒假话，而那恰好是有人盯着看的时刻）；页面**内容没变就不重绘**（每 3 秒无条件重建 DOM 会让按钮在鼠标底下换掉、展开的连接串每 3 秒消失、操作流的滚动位置被重置）。

`tests/support/live.ts` 是驱动**正在运行的**本地栈的辅助层（`preflight` / `createProject` / `settle` / `psqlThroughProxy` / `waitFor`）。`proxy-connect`、`tenant-isolation`、`directus-on-control-plane` 三个 e2e 都建在它上面：它们必须打真实部署路径，而 proxy 容器的 `--auth-endpoint` 里烧死了一个控制面地址，所以这些用例不能像 `full-lifecycle` 那样自建进程内 app。

## 完成定义（DoD）

一个任务算完成，必须同时满足：
1. `pnpm verify` 全绿（typecheck + lint + unit + contract）。
2. 涉及外部行为的，e2e 用例存在且跑过。
3. 文档回写：新事实进 002 对应小节，`[?]` 变 `[F]`/`[C]`。
4. 不引入未在 002 §1 列出的依赖；新增依赖需在本文追加一行说明理由。
